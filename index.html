LEARN MODE

Paging Theory

Use these short notes before running the simulator. They are also useful for viva preparation.

🧠

What is Memory Management?

Memory management is the OS function responsible for allocating, tracking and protecting main memory for processes. It decides where process data can reside and how addresses are translated.

▦

What is Paging?

Paging divides logical memory into fixed-size pages and physical memory into fixed-size frames. A page can be placed in any available frame, so a process does not need one contiguous block of physical memory.

🔖

Page Table

A page table stores the mapping from a page number to a frame number. A valid bit indicates whether the page currently has a valid frame mapping.

⚡

TLB

The Translation Lookaside Buffer is a small, fast cache containing recently used page-to-frame mappings. A TLB hit avoids a page-table lookup; a miss requires checking the page table.

🎯

Logical Address

A logical address is divided into a page number and an offset. For a page size P: page = floor(address / P) and offset = address mod P.

📍

Physical Address

After finding the frame, the physical address is calculated as frame × page size + offset. The offset remains unchanged during translation.

⚠

Page Fault

If a requested page is not currently mapped to a valid frame, the simulator reports a page fault. In a real OS, the OS may load the page from secondary storage.

↔

Why Paging?

Paging supports non-contiguous allocation and avoids external fragmentation. The trade-offs include page-table overhead and possible internal fragmentation.
